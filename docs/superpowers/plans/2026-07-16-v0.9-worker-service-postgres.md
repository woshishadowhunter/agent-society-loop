# v0.9 Worker Service and PostgreSQL Runtime Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a lease-maintained worker process and a network-safe PostgreSQL execution backend without weakening v0.8 fencing guarantees.

**Architecture:** Planning is separated from execution. Workers atomically discover ready tasks through one repository contract, perform slow work outside transactions while a separate connection renews ownership, and commit outcomes plus terminal goal state in one fenced transaction. SQLite and PostgreSQL implement the same conformance tests; PostgreSQL never dual-writes to SQLite.

**Tech Stack:** Python 3.10+, stdlib threading/signals/unittest, SQLite, PostgreSQL, optional psycopg 3, GitHub Actions PostgreSQL service.

## Global Constraints

- Preserve the zero-dependency SQLite default install.
- Add PostgreSQL only through the `postgres` optional dependency.
- Never hold a database transaction during model, remote-agent, reviewer, or tool execution.
- Never persist output after lease ownership is lost.
- Use one database as the transaction authority for a claimed task.
- Preserve all 213 v0.8 tests and Python 3.10-3.14 compatibility.
- Do not claim exactly-once semantics for external side effects.
